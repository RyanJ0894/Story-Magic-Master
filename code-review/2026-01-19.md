## 1. Architecture Review

### 1.1 Strengths

1. **Clean Monorepo Structure**
   - Clear separation: web (frontend), orchestrator (backend)
   - pnpm workspaces with proper dependency management
   - Shared TypeScript configuration

2. **Consolidated Backend**
   - Director agents and orchestration in single service
   - Eliminates inter-service HTTP overhead
   - Unified TypeScript types throughout

3. **Background Job Pattern**
   - Non-blocking generation via `setImmediate()`
   - Job progress tracking in database
   - User can leave page without killing job

4. **Database Design**
   - Proper RLS policies for multi-tenancy
   - JSONB for flexible schema (progress, director_json)
   - Billing period tracking with usage limits

### 1.2 Concerns

1. **`setImmediate()` Pattern Fragility**
   - **File:** `packages/web/app/api/generate/route.ts:230`
   - Works on Render (persistent Node process) but NOT serverless
   - If web service restarts mid-job, background work is lost
   - **Recommendation:** Use proper job queue (BullMQ, Inngest, or Trigger.dev)

2. **Service Role Key in Frontend**
   - **File:** `packages/web/app/api/generate/route.ts:22-23`
   - Service role key used in Next.js API route
   - Could be exposed via source maps or error messages
   - **Recommendation:** Move heavy processing to dedicated backend service

3. **Missing Health Check Dependencies**
   - **File:** `packages/orchestrator/src/routes/health.ts`
   - Only returns static info, doesn't check:
     - Database connectivity
     - Redis availability
     - FFmpeg binary
     - ElevenLabs API health
   - **Recommendation:** Add deep health checks with `/health/live` and `/health/ready`

## 2. Security Analysis

### 2.1 Critical Issues

1. **CRITICAL: Hardcoded Credentials in .env.local**
   - **Files:** `.env.local`, `packages/web/.env.local`
   - Service role keys, API keys stored in tracked files
   - `.env.local` is gitignored but pattern is risky
   - **Action:** Audit git history for accidental commits, rotate all keys

2. **CRITICAL: No Input Sanitization on Script Text**
   - **File:** `packages/web/app/api/generate/route.ts:65`
   - `script_text` passed directly to LLM without sanitization
   - Potential prompt injection vector
   - **Action:** Add input validation, length limits, content filtering

3. **CRITICAL: Missing CSRF Protection**
   - **Files:** All API routes
   - POST endpoints rely only on auth header
   - No CSRF tokens for state-changing operations
   - **Action:** Implement CSRF middleware for mutations

### 2.2 High Priority Issues

4. **Service Role Key Exposure Risk**
   - **File:** `packages/web/app/api/generate/route.ts:22`
   - `SUPABASE_SERVICE_ROLE_KEY` used client-side (in API route)
   - If error stack trace leaks, key could be exposed
   - **Recommendation:** Use separate backend service with service role

5. **Rate Limiting Bypass**
   - **File:** `packages/orchestrator/src/middleware/rate-limit.ts:58`
   - Falls open if Redis unavailable: `return next()`
   - Attacker could DoS Redis then flood API
   - **Recommendation:** Fail closed or use in-memory fallback

6. **Missing Content-Security-Policy**
   - **File:** `packages/web/next.config.js`
   - No CSP headers configured
   - **Recommendation:** Add strict CSP via middleware

7. **JWT Token Not Validated for Expiry**
   - **File:** `packages/orchestrator/src/middleware/auth.ts`
   - Relies on Supabase to validate token
   - Should explicitly check `exp` claim
   - **Recommendation:** Add explicit expiry check

### 2.3 Medium Priority Issues

8. **Overly Permissive CORS**
   - **File:** `packages/orchestrator/src/index.ts:28`
   - `credentials: true` with configurable origins
   - Production should use strict allow-list
   - **Recommendation:** Audit CORS_ORIGINS in production

9. **Missing Request Size Limits**
   - **File:** `packages/orchestrator/src/index.ts`
   - No explicit body size limit for `/generate-scenes`
   - Large scripts could exhaust memory
   - **Recommendation:** Add `express.json({ limit: '1mb' })`

10. **Sensitive Data in Logs**
    - **File:** `packages/orchestrator/src/lib/logger.ts`
    - Redacts `authorization` but not custom headers
    - User IDs logged in plain text
    - **Recommendation:** Review log output for PII

## 3. Performance Analysis

### 3.1 Bottlenecks Identified

1. **TTS Concurrency Limit**
   - **File:** `packages/orchestrator/src/orchestrator/workers/tts.ts`
   - Limited to 3 concurrent ElevenLabs calls (pLimit)
   - For 30-line scripts, this creates significant queue time
   - **Recommendation:** Increase to 5-10 based on ElevenLabs tier

2. **Synchronous Scene Processing**
   - **File:** `packages/orchestrator/src/orchestrator/pipeline.ts`
   - Scenes processed sequentially, not in parallel
   - Each scene waits for previous to complete
   - **Recommendation:** Parallelize independent scene processing

3. **No TTS Result Streaming**
   - **File:** `packages/orchestrator/src/lib/audio.ts`
   - Waits for full TTS response before processing
   - Could stream audio chunks for faster time-to-first-byte
   - **Recommendation:** Investigate ElevenLabs streaming API

4. **Large Audio Files in Memory**
   - **File:** `packages/orchestrator/src/orchestrator/workers/export.ts`
   - `fs.readFileSync(episodePath)` loads entire file
   - For long scripts, could be 100MB+
   - **Recommendation:** Use streams for upload

### 3.2 Database Query Optimization

5. **N+1 Query in Audio Outputs**
   - **File:** `packages/web/app/api/generate/route.ts:120-139`
   - Inserts audio outputs one at a time in loop
   - **Recommendation:** Batch insert with single query

6. **Missing Database Indexes**
   - **File:** `packages/web/supabase/migrations/`
   - No explicit indexes on:
     - `jobs.project_id`
     - `jobs.status`
     - `usage.user_id, usage.period`
   - **Recommendation:** Add indexes for common queries

## 5. Code Quality Issues

### 5.1 TypeScript Issues

1. **Excessive Type Assertions**
   ```typescript
   // packages/orchestrator/src/lib/audio.ts:12
   const ffmpeg = ffmpegStatic as unknown as string;
   ```
   - Multiple `as unknown as` patterns indicate type definition issues
   - **Fix:** Create proper type declarations or use type guards

2. **Any Types**
   ```typescript
   // packages/orchestrator/src/lib/llm-client.ts
   tools: Record<string, any>
   ```
   - Loses type safety for tool definitions
   - **Fix:** Define proper tool interfaces

3. **Non-null Assertions**
   ```typescript
   // packages/web/app/api/generate/route.ts:21
   const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL!;
   ```
   - Runtime error if env var missing
   - **Fix:** Add runtime validation with Zod

### 5.2 Error Handling Issues

4. **Generic Error Messages**
   ```typescript
   // packages/web/app/api/generate/route.ts:186
   return NextResponse.json({ error: 'Generation failed' }, { status: 500 });
   ```
   - Hides actual error from user
   - **Fix:** Return structured error with code and safe message

5. **Swallowed Errors**
   ```typescript
   // packages/orchestrator/src/lib/storage.ts:84
   } catch (err) {
     console.error('Supabase upload error:', err);
   }
   ```
   - Error logged but not propagated
   - **Fix:** Throw or return error result

6. **Missing Error Boundaries**
   - **File:** `packages/web/app/`
   - No React error boundaries for component failures
   - **Fix:** Add error.tsx for each route segment

### 5.3 Code Smells

7. **Long Functions**
   - `packages/orchestrator/src/orchestrator/pipeline.ts` - 200+ lines
   - `packages/web/app/api/generate/route.ts` - 260 lines
   - **Fix:** Extract into smaller, focused functions

8. **Magic Strings**
   ```typescript
   // Multiple files
   status: 'completed' | 'failed' | 'processing' | 'queued'
   ```
   - Duplicated across codebase
   - **Fix:** Create shared constants/enums

9. **Implicit Dependencies**
   - FFmpeg path resolution relies on node_modules structure
   - Whisper binary path hardcoded
   - **Fix:** Use dependency injection or explicit configuration

## 10. Conclusion

Story Magic has a solid foundation with good architectural decisions (monorepo, TypeScript, Supabase). The recent consolidation was the right call. However, the background job pattern and security concerns need immediate attention before scaling.

**Priority Order:**
1. Security (API keys, input validation, CSRF)
2. Reliability (job queue, error handling)
3. Testing (coverage to 60%)
4. Performance (TTS concurrency, parallelization)
5. Cleanup (remove Python director, documentation)

**Estimated Total Effort:** 80-120 developer hours
