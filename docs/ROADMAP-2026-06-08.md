#### #161 — Stale `directorJson` reused after script edit (2 SP)

**File:** `packages/orchestrator/src/processor.ts:136`

**Root cause:** `hasExistingParse` checks only existence, not whether the parse corresponds to the
current `scriptText`.

**Fix:**
```typescript
// Add scriptText hash to directorJson metadata when writing
// packages/orchestrator/src/processor.ts — in the director call result write path:
const scriptHash = crypto.createHash('sha256').update(scriptText).digest('hex');
// Store hash alongside directorJson in the DB (project.directorJsonHash or inline in directorJson.meta)

// At processor.ts:136, replace:
const hasExistingParse = Array.isArray(existingDirectorJson?.scenes) && existingDirectorJson.scenes.length > 0;
// With:
const existingHash = existingDirectorJson?.meta?.scriptHash;
const currentHash = crypto.createHash('sha256').update(scriptText).digest('hex');
const hasExistingParse = Array.isArray(existingDirectorJson?.scenes)
  && existingDirectorJson.scenes.length > 0
  && existingHash === currentHash;
```

**Schema change:** Add `directorJsonHash TEXT` column to `projects` table (or embed hash in `directorJson.meta` — no migration needed if embedded).

**Tests to write:**
- `processor.test.ts`: cached directorJson is skipped when scriptText changes
- `processor.test.ts`: cached directorJson is reused when scriptText is unchanged

#### #163 — Silent voice fallbacks (3 SP)

**Files:**
- `packages/orchestrator/src/director/agents/voice-assignment-agent.ts:134`
- TTS generation layer (wherever per-character TTS calls fall back to default voice)

**Root cause:** 3 independent silent fallback layers:
1. LLM parse failure → `buildFallbackVoiceMap()` called silently
2. Missing `voiceId` after assignment → default voice substituted without warning
3. TTS generation failure → default voice used, job continues

**Fix:** Add a `warnings: string[]` field to job output. Each silent substitution appends a warning.
Surface warnings in the project page UI as a collapsible "Audio notes" section.

```typescript
// In voice-assignment-agent.ts, replace silent fallback:
// BEFORE: return buildFallbackVoiceMap();
// AFTER:
warnings.push(`Voice assignment failed (LLM parse error) — all characters assigned default voice`);
return { voiceMap: buildFallbackVoiceMap(), warnings };
```

**Backend schema:** Add `warnings JSONB DEFAULT '[]'` to `jobs` table.
**Frontend:** Show `warnings` array in project page if non-empty (yellow info card, not error).

**Tests to write:**
- `voice-assignment-agent.test.ts`: fallback returns warning in result
- `processor.test.ts`: warnings from voice agent are persisted to job record
- Component test: project page shows warning card when job has warnings

#### #166 — Missing audio tracks silently dropped (1 SP)

**File:** `packages/orchestrator/src/orchestrator/shared/resolve-cues.ts`

**Root cause:** `resolveCuesToMixInputs()` logs a `warn` and skips unresolvable tracks. Job completes with
missing music/ambience/SFX.

**Fix:** Return unresolved track IDs in the function's return value, append to job `warnings[]`.

```typescript
// resolve-cues.ts — extend return type:
type ResolveCuesResult = {
  inputs: MixInput[];
  unresolved: { layer: 'music' | 'ambience' | 'sfx'; trackId: string }[];
};

// Caller in orchestrator pipeline: merge unresolved → job warnings
```

**Tests to write:**
- `resolve-cues.test.ts`: missing track ID returns in `unresolved` array (not silent skip)

### PR D-2: `fix/user-errors-shared-projects-timeout` (~4 SP)

**Closes: #141, #143, #144**

#### #141 — Raw backend errors returned to user (1 SP)

**File:** API route error handlers in `packages/web/app/api/`

**Root cause:** Director Agent error response `{ "message": "invalid x-api-key", ... }` is passed
directly to the frontend toast.

**Fix:** Error sanitization middleware / wrapper. Map known error types to safe user messages:
```typescript
// packages/web/lib/errors.ts — add sanitizeJobError():
const SAFE_MESSAGES: Record<string, string> = {
  'invalid x-api-key': 'AI service configuration error. Please contact support.',
  'fetch failed': 'Generation service unavailable. Please try again.',
};
export function sanitizeJobError(raw: string): string {
  for (const [pattern, safe] of Object.entries(SAFE_MESSAGES)) {
    if (raw.toLowerCase().includes(pattern)) return safe;
  }
  return 'Audio generation failed. Please try again or contact support.';
}
```

**Tests:** `errors.test.ts`: sanitizeJobError maps known patterns and returns generic message for unknown.

#### #165 — Voice catalog validation script (1 SP)

**File:** `packages/orchestrator/scripts/validate-voice-catalog.ts`

Script that:

2. Calls ElevenLabs `GET /v1/voices` with `ELEVENLABS_API_KEY`
3. Cross-references: which catalog IDs are missing from ElevenLabs account?
4. Prints table: ✅ valid | ❌ not found | ⚠️ metadata mismatch (name/gender/tone)

Run before any deploy that touches voice catalog. Add to CI as an optional check.

#### #148 — Voice assignment enforcement (4 SP)

**Root cause (after running #165):** LLM prompt does not strictly constrain output to catalog IDs.
VoiceAssignmentAgent accepts any ElevenLabs voice ID the model produces.

**Fix — two layers:**

**Layer 1: Prompt hardening**
```typescript
// voice-assignment-agent.ts — system prompt addition:
`You MUST only assign voices from the following catalog. 
Voice IDs not in this list are INVALID and will be rejected.
Catalog: ${JSON.stringify(catalogIds)}`
```

**Layer 2: Post-parse validation**
```typescript
// After parsing LLM output:
for (const [character, assignment] of Object.entries(voiceMap)) {
  if (!catalogIds.has(assignment.voiceId)) {
    // Reject entire assignment, retry with stricter prompt (up to 2 retries)
    // If still invalid after retries: add to job warnings, use nearest-match from catalog
    warnings.push(`Invalid voice ID ${assignment.voiceId} for ${character} — reassigned to nearest match`);
    voiceMap[character] = findNearestCatalogVoice(assignment, catalog);
  }
}
```

**Tests:**
- `voice-assignment-agent.test.ts`: non-catalog voiceId triggers warning + nearest-match reassignment
- `voice-assignment-agent.test.ts`: valid catalog voiceId passes without warning
- `voice-catalog.test.ts`: `findNearestCatalogVoice` returns correct gender/tone match
