### Issue 2: Voices heard that are not in Ryan's ElevenLabs library

**Status: ✅ FULLY RESOLVED** (2026-05-19/20)

**Root cause (layered — four separate problems fixed):**

**2a. Stale voice catalog** (commit `ecd8e92`)
The primary catalog file had 80 entries baked in from a historical snapshot. Ryan's current ElevenLabs account only has 29 voices; 72 of the catalog IDs were no longer valid. The director assigned stale IDs that ElevenLabs rejected or substituted with arbitrary voices.

*Fix:* Rebuilt both catalog files from Ryan's live `/v1/voices` API call. 29 valid entries only. Distribution: Narrator×3, Older Male×10, Older Female×4, Male 20s-30s×4, Female 20s-30s×6, Male Teen×2.

**2b. Voice metadata label conflicts causing age misclassification** (commit `34263af`)
After the rebuild, `voices_metadata.json` still had 13 conflicting labels (e.g. "Male 30s to 40s" vs "Older Male"). The metadata file wins the merge, so Ryan's entire older-male cohort was being scored as young-adult — producing vocal mismatches even with valid IDs.

*Fix:* Reconciled all 13 label/tone/style conflicts. Both files now agree.

**2c. Voice deduplication not enforced** (commit `5f96204`)
The voice assignment agent had a `scopedUsedVoiceIds` Set that was intended to prevent the same voice being assigned to two characters, but nothing ever wrote to it. Scripts with multiple similar characters (e.g. two young female leads) would silently receive the same voice.

*Fix:* Added `commit_voice(voice_id, character_name)` as a new LLM-callable tool. After choosing a voice, the LLM calls `commit_voice`, which writes the ID to the Set. Subsequent `search_voices` calls exclude all committed IDs via `excludeVoiceIds`. The prompt now requires `commit_voice` after every assignment.

**2d. Voice catalog refresh script** (commit `34263af`)
No mechanism existed to detect or recover from catalog drift. The only way to refresh was to manually re-run the Python rebuild script.

*Fix:* `packages/orchestrator/scripts/refresh-voice-catalog.ts` — callable via `pnpm refresh:voices`. Pulls live voices, rebuilds both files, reconciles labels, verifies default voice IDs are still present, prints added/removed summary.

## Bugs Fixed This Week (Not Tracked as GitHub Issues)

### Bug A: Audio static noise on playback

**Status: ✅ RESOLVED** | Commits: `1cc84ed`, `8a79393`, `25b287f`, `b0514c6`, `b674b5f`

**Root cause:** Relative audio file paths (e.g. `audio/job123/episode.m4a`) were passed directly to `new Audio()` in browser components. The browser resolved them against the web origin (port 22000), got a 404 HTML error page, and played the HTML bytes as noise.

**Fix — four layers:**
1. `resolveAudioUrl(filePath)` function created in `lib/resolve-audio-url.ts`
2. Applied to all five audio player components: `AudioPlayer`, `RunHistory`, `RunComparison`, `ScreenplayReader`, `ScriptSyncPlayer`
3. Applied to the public-share API endpoint (`/api/shares/access/[code]/route.ts`) — share-link viewers were still hitting this bug
4. `resolveAudioUrl` hardened: null/undefined guard, regex http-check (replaces fragile `startsWith('http')`), strips leading slash from relative paths, strips trailing slash from base

**Regression tests added** (`0e0a4c4`)

---

### Bug B: Team invite "Invalid Request Parameters"

**Status: ✅ RESOLVED** | Commits: `1cc84ed`, `b0514c6`

**Root cause:** When an enterprise admin invited a new team member, the Clerk invitation was created before `ensureProfile()` had created the invitee's profile row. When the invitee accepted, `teamMember.update` wrote `userId: <clerk_id>` which violated the FK constraint (`TeamMember.userId → Profile.id`).

**Fix:**
- `ensureProfile(userId)` is now called at invite-accept before any DB write
- `ensureProfile` itself hardened: `findUnique + create` (non-atomic, race condition on double-click) replaced with `prisma.profile.upsert` — single atomic statement, no P2002 on concurrent accepts
