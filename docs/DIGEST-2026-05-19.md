## The Two Bugs You Reported — Fixed

### 1. Audio Generating Static Noise

**What was happening:** When a project generated new audio, the player received a relative file path like `output-run3.m4a` instead of a full URL. The browser resolved that path against the web app domain (`storymagicapp.net/output-run3.m4a`) — which returns a 404 HTML error page. The audio engine then tried to decode that HTML page as audio, producing the static noise you heard.

**Why it was missed:** This worked correctly during early development because the web app and orchestrator ran on the same server. Once they were split across two Render services, relative paths broke — but only for *newly generated* files. Older projects that already had absolute URLs stored in the database played fine, so the bug only showed up when someone ran a new generation in production.

**The fix:** A single `resolveAudioUrl()` utility that converts relative paths to full orchestrator URLs. Applied to all five audio player components. Any future player must use this utility — it's the single source of truth.

---

### 2. Team Invite "Failed to Accept" Error

**What was happening:** When a new user received a team invite and clicked Accept *before* ever visiting their dashboard, the invite acceptance failed with a database constraint violation. The team member table has a foreign key requiring a matching row in the profiles table, but new Clerk users don't get a profile row until they visit the app for the first time.

**Why it was missed:** In testing, the invite flow was always tested by users who were already logged in with an established profile. The edge case of *brand new user clicks invite link as their first action* was never covered. This is a common onboarding path for enterprise team members who receive an invite before signing up.

**The fix:** An `ensureProfile()` call is now made immediately after auth verification on the invite accept route — it creates the profile row if one doesn't exist, then proceeds. Safe for all users (no-op if profile already exists).

### UX: 14 New Issues Found, 3 Fixed Today

The Sprint M annotation features (screenplay notes, reactions) had three accessibility/safety gaps that were fixed today:

**ScreenplayPlayer annotations now work on mobile/touch.** The hover-to-annotate system was previously mouse-only — completely invisible on iPad and iPhone, which is the primary enterprise use case (readers reviewing scripts at screenings on tablets). Fixed by adding keyboard focus and touch event handlers so the annotation buttons appear on tab/focus, not just mouse hover.

**Note save failures are no longer silent.** If a network error occurs while saving a note, the app now reopens the note editor so you don't lose your work, and shows a toast explaining what happened. Previously the note would just disappear.

**Delete note now asks for confirmation.** A single accidental tap could permanently delete a note with no warning. Now requires confirmation.

**AudioChooser scenes start collapsed.** When you opened the audio customization panel with a long script, it displayed 90+ expanded scene sections simultaneously — extremely hard to navigate. Scenes now start collapsed; you expand only what you need. The "Expand all / Collapse all" toggle was already there.

The remaining 11 UX findings (P1 and P2) are tracked for Sprint N.

### Database: Critical FK Gap Closed

A foreign key constraint on the `project_comments` table was missing from the database since Sprint M shipped — meaning if a user account was deleted, their comments would become orphaned rows with no parent. This was a carryover finding from three sprints ago that slipped through migration review.

**Migration 0025** (applied in today's deploy) adds that constraint plus three other index fixes:
- The missing FK
- An index name that was mismatched from what Prisma expects (caused permanent false-positive drift warnings)  
- A race-condition guard on the reaction upsert (prevents duplicate reaction rows under concurrent requests)
- Re-assertion of the progressive playback polling index (prevents it from being silently dropped during maintenance)

The reaction upsert code was also wrapped in a database transaction so the delete-then-insert is atomic.

**The audio bug** came from an environment split that didn't exist when the code was written. The pattern was technically correct in a single-server setup.

**The invite bug** came from a gap in test coverage — the new-user-first-action path wasn't represented. Both now have regression tests.

**The database FK** was missed in a prior sprint's migration review because the prior sprint fixed several similar FKs, and this one was incorrectly marked complete in the review TODO. Migration review is easy to rubber-stamp when a batch of fixes looks similar.
