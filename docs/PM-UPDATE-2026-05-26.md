## 1. Bug Fixes You Reported (May 17–18)

### Audio Static After Playback Completion
**What was wrong:** When the audio player reached the end of a track, subsequent plays would generate a static/distorted sound instead of clean audio. Root cause: the audio engine was reusing a completed audio context without resetting it.

**What was fixed:** Audio contexts are now properly torn down and rebuilt on each new playback session. Added a `resolveAudioUrl` utility applied consistently across all three player components (main player, screenplay reader, protected player).

**Result:** Clean audio on every play, including repeat plays of the same track.

---

### Team Invites — "Invalid Request Parameters"
**What was wrong:** When inviting a sub-account user (a team member who joins under your organization), the invite flow was failing with a cryptic "Invalid Request Parameters" error. Two separate issues were identified:

1. A foreign key violation — the database required a `userId` on invite records before the invited user had completed sign-up
2. The Clerk API call was using a deprecated parameter format

**What was fixed:** Invite records now use a nullable `userId` that's populated when the invitee completes onboarding. Clerk API call updated to current spec. The full invite → accept → team membership flow now works end-to-end.

**Result:** Team invites work reliably. You can now invite collaborators and they land in the right organization.

## 2. Voice System Improvements (May 19–20)

### Voice Catalog Refresh
The voice catalog was refreshed directly from your live ElevenLabs account — pulling in the exact voices you have available, with accurate names, voice IDs, and labels. Female teen placeholder voices were also added (these are tagged as pending your catalog additions in ElevenLabs, but the system will assign them correctly once you add them).

### Voice Deduplication Fix
**What was wrong:** In long scripts, the same character could be assigned different voice IDs across scenes — meaning a character would sound like a different person mid-story. This was especially noticeable in 15+ page scripts.

**What was fixed:** A `commit_voice` tool now locks character-to-voice assignments for the duration of a script. Once a character is given a voice, that assignment is held in a scoped map for the full script. The VoiceAssignmentAgent checks this map before assigning any voice, preventing drift.

**Result:** Character voices are now consistent throughout a script regardless of length.

## 6. Sharing Features — Sprint v3.1 (May 26)

This was the main feature sprint. The goal: let you send a script to industry contacts (agents, managers, producers) and know exactly who listened.

### Bulk Share — Send to Multiple People at Once
From any project, you can now open the Share dialog, switch to the "Send to..." tab, and send personalized email invites to up to 20 people in one action. Each recipient gets:
- Their own unique link (so you can track them individually)
- A personalized message with their name substituted in (`{name}` placeholder)
- Configurable expiry (7/30/90/365 days or never)

The "Send to..." label is intentionally generic — works for agents, managers, producers, directors, or anyone else you want to share with.

### Share Dashboard — Who Opened, Who Listened
Each project now has a `/projects/[id]/shares` page showing every share you've ever sent. The dashboard shows:
- **Total sent** — number of share links created
- **Opened** — recipient clicked the link
- **Listened** — recipient pressed play (confirmed by audio event, not just page load)
- **Not opened** — link was sent but never clicked

Per-recipient row shows: their email/name, when you sent it, their current status (Listened / Opened / Not Opened / Deactivated / Expired), last activity, and play count. You can copy their specific link or deactivate it per-row.

### Play Analytics
Every time a recipient presses play on their share link, the system now records:
- The event (play vs. complete)
- Their IP address (for general location)
- Their browser/device
- The timestamp

This data powers the "Listened" status in the share dashboard.

### Revoke Access
- **Per-link revoke:** deactivate any individual share with a confirmation prompt
- **Revoke all:** a single button deactivates all active shares for a project (with confirmation showing the count)

### Share Link Protections
Share links now enforce their constraints even when marked active:
- **Expiry:** links past their expiry date are rejected at the server (previously, an active link would work even if past its set expiry)
- **Play limit:** links that have hit their maximum play count are rejected (previously, the play limit could be bypassed by concurrent requests — this was a race condition; fixed with atomic database operations)

## 7. Code Review Findings & Security Fixes (May 26)

A full code review ran in parallel with the sharing sprint. Two critical bugs were found and fixed:

**Critical: Play count race condition**  
The old play tracking used a read-then-write pattern: read the current count, add 1, write back. If two play events arrived simultaneously (common if a page loads slowly), both could read the same count and one play would be lost. Fixed with an atomic database increment that's safe under any concurrency.

**Critical: Share expiry bypass**  
A share link's expiry and play limit were only enforced if the link was marked "inactive" — but shares that hit their expiry stayed "active" in the database until cleaned up. An expired or exhausted share could still accept plays. Fixed with explicit checks that run before any play is counted, regardless of the active flag.

**P1: Error message in preview button never showed**  
The audio preview button (`Preview` on each scene in the project editor) tracked error state internally but the error message was never rendered in the UI. Users who hit a preview generation error saw a red "Retry" icon with no explanation. Fixed — error now appears as a tooltip on hover.
