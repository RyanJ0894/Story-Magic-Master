### Step 1 — PR: `fix/credits-and-notes` (Issues #93 + #97)

**No dependencies. Blocking all pipeline testing.**

#### Issue #93 — Insufficient Credits

**Root cause:** `app/api/generate/route.ts` line 106:
```typescript
const PAID_TIERS = new Set(['creator', 'pro', 'studio']);
```
There is no `enterprise` tier in the `SubscriptionTier` type. Test accounts on `free` tier hit the credit gate. Once per-session credits exhaust (1 credit/scene), all further generation attempts return 402 `INSUFFICIENT_CREDITS`.

**Fix (two parts):**
1. Add admin endpoint `POST /api/admin/credits/grant` — body: `{ userId, amount }`. Admin-only. Updates `Profile.credits += amount` and records a `CreditTransaction`.
2. Add "Grant Credits" button to the existing `/admin/users` page (already shows user list). Clicking opens a dialog: user, amount, reason.

**Test:**
- Unit: credit grant endpoint — admin-only, adds correct amount, records transaction
- Playwright: admin logs in → `/admin/users` → grant 100 credits to test user → verify balance via `/api/credits/balance`

#### Issue #97 — Script Notes Not Saving

**Root cause (best hypothesis without Console Copy 22):**
`app/api/projects/[id]/comments/route.ts` calls `auth()` directly, not `withAuth`. If the Clerk session token has expired by the time the user tries to save a note (e.g., after a 3.5-minute audio generation), `auth()` returns `{ userId: null }` and the route returns 401.

Secondary hypothesis: the `ProjectComment.author` Prisma relation requires a `Profile` row matching `userId`. The comments route does NOT call `ensureProfile`. If the Profile is somehow missing, `prisma.$transaction` throws a FK violation (P2003).

**Fix:**
1. Add `ensureProfile` call before the transaction (fallback protection)
2. Add specific error logging: `log.error('[Comments] POST failed', { status, error })` on non-ok responses in the route
3. Return the HTTP status code in the toast message client-side so the user knows if it's auth vs server error

**Test:**
- Unit: POST with valid auth → 201, comment returned; POST without auth → 401; POST to unowned project → 404
- Playwright: generate audio → wait for completion → save a note on screenplay → verify note appears in NotesPanel

### Step 2 — PR: `fix/session-polling` (Issue #92 + STORY-MAGIC-6)

**Depends on:** Nothing. More valuable once #93 is fixed (can test full pipeline).

#### Issue #92 — Session Expired After Audio Generation

**Root cause:**
`lib/api/fetch.ts` `apiFetch` only adds `X-Requested-With` — it does NOT call `useAuth().getToken()` to get a fresh Clerk JWT. During a 3.5-minute generation, if the browser tab goes to background or the device semi-sleeps, Clerk's client-side token refresh may not fire. Polls to `/api/jobs/${jobId}` return 401. After 3 consecutive 401s, the "Session expired" toast appears and polling stops.

The 2/3 reload failure rate confirms the orchestrator was also failing (likely credit exhaustion — same user running multiple tests). The "Session expired" message is misleading when the real cause is insufficient credits causing the orchestrator to 402-fail.

**Fix:**
1. In `generate-button.tsx`, use `useAuth().getToken()` to inject a fresh Bearer token on each poll call (replace `apiFetch` with an explicit `Authorization: Bearer` header approach for the polling calls)
2. On `consecutiveAuthFailures >= 3`, don't stop polling — instead, attempt a single page reload (not a toast) so the server-rendered component can show the final job state
3. Add a "check status" link on the "Session expired" toast so the user can manually recover

**Also fix in same PR:** Remove the "Session expired — please reload" wording. Replace with: "Connection lost — your audio may be ready. [Check status →]" with a link to `router.refresh()`.

**STORY-MAGIC-6 fix:** The hydration error fires on every Playwright E2E run against production because the service worker tries to register on page load and throws. Add a guard in the SW registration:
```typescript
if (typeof window !== 'undefined' && !navigator.webdriver) {
  registerSW(); // skip in Playwright/automated contexts
}
```

**Test:**
- Unit: `pollJobStatus` with 3× 401 response — shows toast with "Check status" link, does NOT call clearInterval permanently
- Playwright: mock a slow job → verify the player renders when job completes even if 401s occur
